# Memoria.ia Server structural memory client V1

Status: transport gate only; not yet wired into the normal chat loop.

## Purpose

This gate lets OFF.IA call the authenticated structural-text endpoints exposed by
Memoria.ia Server without embedding the Memoria.ia administrative API key in the
APK.

Flow:

```text
OFF.IA
  -> DeviceTokenProvider
  -> Authorization: Device <short-lived token>
  -> Memoria.ia Server /device/memory/structural/*
  -> memory.sync authorization
  -> server-derived device hierarchy
  -> internal X-Memoria-Key
  -> Memoria.ia structural text recall
```

## Android boundary

`MemoriaServerStructuralClient` exposes:

- `observeUserText(text, sequence, sessionId)`
- `resolve(query, limit, maxScan)`

The client sends only user payload. It has no API for `hierarchy_id`,
`source_id` or `source_kind`; those remain Server-owned.

The client fails closed if the Server ever reports
`semantic_projection=true`, because this gate is specifically for the
non-semantic structural field.

## Token boundary

The client receives tokens through `DeviceTokenProvider`. The branch now
contains the first device-identity gate:

- one-time enrollment claim using the Server invitation code;
- Ed25519 key-pair generation on-device;
- public key persisted as the registered device identity;
- private PKCS#8 key material encrypted with AES-GCM;
- temporary plaintext PKCS#8 buffers are zeroed after wrap/restore;
- AES wrapping key is generated inside AndroidKeyStore and is non-exportable;
- binding to exactly one Server/device pair, with silent rebinding rejected;
- exact challenge-message signing;
- short-lived Device token kept only in RAM;
- automatic token renewal before expiry.

The Ed25519 private key itself is not stored plaintext, the one-time enrollment
code is not persisted by the UI, and the Server administrative key is never
present on the device.

The branch deliberately does not assume AndroidKeyStore can generate Ed25519.
Instead, the protocol key pair is generated by the Java Ed25519 provider and the
private key is wrapped at rest by an AES key owned by AndroidKeyStore.

## Current non-goal

This branch does not replace `MemoryGateway`, the RC6 local runtime, BDR, or
the existing Curiosity flow. It establishes the authenticated Server transport
and device identity required before the structural V2 path can be connected to
chat.

The next gate is UI/onboarding plus a real-device acceptance:

```text
admin creates enrollment invitation with memory.sync
  -> OFF.IA claims invitation
  -> admin approves device
  -> OFF.IA challenge/sign/verify
  -> observe structural user text
  -> resolve structural context
  -> force-stop/reopen
  -> resolve again with the same device identity
```
